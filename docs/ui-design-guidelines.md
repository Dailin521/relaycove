# RelayCove 客户端 UI 设计约束

本文档是 RelayCove Windows 客户端后续界面设计与实现的共同参考。它记录已确认的视觉、交互和兼容边界，后续 AI 任务应先阅读本文，再修改客户端 UI；如需求与本文冲突，必须在任务记录中明确取舍，不得静默改变既有行为。

## 布局与层级

- 主窗口采用浅灰画布上的白色内容区，保持左侧会话栏、中间聊天区、可展开右侧成员栏的三栏结构。
- 左侧会话固定分为公开频道、私有频道、私聊三组。分组标题可折叠；折叠状态只影响显示，不删除会话、未读数或当前选择。
- 公开频道和私有频道分组标题旁保留“+”创建入口；私聊组不显示创建频道入口。
- 账户、更新、退出、服务器地址和诊断信息属于低频功能，放在左栏底部展开区。
- 窄窗口优先保证聊天内容、输入区和发送按钮可用；右侧成员栏在小于 1400 像素时自动收起，不挤压聊天区。

## 会话与成员

- 会话项必须显示类型图标、名称、预览、时间、选中态和未读徽标；不得用颜色单独表达类型或状态。
- 频道成员栏支持搜索；私有频道可在权限允许时添加和移除成员，危险移除操作使用红色。
- 私聊成员栏显示该私聊的全部参与成员，不显示“可添加成员”目录，也不伪造频道管理能力。
- 当前协议没有逐成员频道角色字段时，只能显示“频道成员/可管理成员”等能力标签；不得猜测或伪造角色。

## 消息、图片和附件

- 消息区使用 Slack/Mattermost 风格的无气泡消息流，显示头像、昵称、时间和正文；连续消息合并，保留回复引用、@提及、日期线和新消息线。
- 图片消息在进入可见消息列表后自动下载并加载安全缩略图；下载完成后自动解码，不要求用户先点击“下载”。
- 图片自动下载必须复用现有授权、缓存、完整性校验、大小限制和取消机制；失败时在消息附近保留清晰的失败状态和“重试”入口。
- 图片缩略图和查看器都必须经过现有安全解码策略；不得直接从远端 URL 绑定 WPF `Image.Source`。
- 普通文件仍显示附件卡片，下载、取消、重试、在文件夹中显示和安全打开行为不得回归。

## 输入区与状态

- 输入区固定在聊天区底部，支持自然多行输入；回复、@候选、附件预览集中在输入区，附件可单独移除。
- 发送成功后清理正文和已发送附件；发送中、失败和重试状态必须就地表达，不遮挡聊天内容。
- 正常同步状态默认隐藏；连接状态使用简短中文。错误提供重试入口，长错误放入可展开详情。

## 视觉规范

- 统一颜色、圆角、间距、字号和按钮高度；白色内容区配浅灰背景，减少大面积蓝色边框和工具软件感。
- 红色只用于危险操作或明确失败状态；悬停、选中、禁用、加载和空状态必须有可辨识但克制的差异。
- 优先使用现有资源和 WPF 原生控件，不引入新的 UI 框架或桌面控制能力。

## 验证要求

- 常用窗口尺寸至少验证 1280×720、1600×900、1920×1080；小窗口下输入区和关键按钮不得裁切。
- UI 对比使用仓库内置 WPF `RenderTargetBitmap`/快照入口；禁止 Windows 应用控制、UI Automation 或桌面自动点击来替代渲染验证。
- UI 变化必须补回归测试；Release 编译要求 0 警告、0 错误。
- 不得修改服务端 API、SignalR、Shared DTO、数据库或消息可靠性语义来解决纯 UI 问题。
