修复 owner 双账号真实试用暴露的五类可见问题，使普通成员能完成频道创建与私有成员邀请，`@用户` 面板打开即显示成员并随输入自动过滤，图片附件可下载预览，非当前会话的新消息能产生 Windows 通知，并在文字发送已可靠落盘后清空未被继续编辑的草稿。

- `已验证`：源码已有 pending 落盘后清空文字的逻辑，但条件绑定过宽的 composer context version，且没有对应 UI 策略回归。
- `已验证`：owner 已明确授权普通成员创建频道，并预授权本切片完成后的合并、推送、构建与必要部署。

### 范围

- 必须实现：
  - 任意正常认证用户可创建 Public/Private；创建者成为会话 Administrator。
  - 会话页展示成员；Public 展示全部正常用户，Private/Direct 展示真实成员且不向无权用户泄露。
  - 普通客户端提供创建频道、私有频道选人/拉人及创建者成员管理入口；新成员在线时由最小 grant 事件触发权威会话刷新，离线仍由既有完整同步恢复。
  - 打开 `@用户` 面板即以空前缀列出最多 50 个当前会话候选，继续输入允许字符时自动前缀过滤，不要求再次点击搜索；处理取消、乱序和会话切换。
  - 修复附件下载地址在任意服务器子路径下的解析，并验证图片下载、缩略图与原图查看链路。
  - 正常前台运行时，非当前会话的新消息仍进入通知决策；当前会话和 WindowActivated 历史恢复仍不弹。
  - 文字 pending 已落盘且用户未继续编辑/切换上下文时清空草稿；未落盘或发送期间继续编辑时保留。
  - 更新工程方案、决策、状态和本任务证据；构建新版自包含客户端并完成双账号实测。
- 允许修改：
  - `src/RelayCove.Shared/`、`src/RelayCove.Server/`、`src/RelayCove.Client/`
  - 对应 `tests/`、`docs/ai/`、工程方案与发布/部署记录
- 明确不做：
  - Web 聊天端、复杂频道角色、邀请审批、组织架构、在线状态系统或 UI 全面换肤。

## 任务结果

### 修改摘要

- 普通正常用户可创建公开/私有频道，创建者成为频道管理员；聊天页显示当前会话成员，并提供创建、拉入和移除入口。
- 新增最小正常用户目录与 participant 投影；公开频道展示全部正常用户，私有/私聊只展示真实成员，外部用户不能读取私有名册。
- 新增 `ConversationAccessGranted` 最小事件；客户端只把它当作权威同步触发，补跑第二轮期间的触发会进入后继 single-flight，离线仍由完整对账收敛。
- `@用户` 面板打开即请求最多 50 人，输入变化 120 ms 防抖自动筛选并丢弃迟到响应。
- 修复 `/relaycove/` PathBase 下附件下载地址解析，恢复既有图片缩略图、原图与下载链路。
- 非当前会话在前台 Reconnect/Periodic 同步后仍可通知；仅 WindowActivated 历史恢复明确抑制。
- 文字 pending 可靠提交后按会话、正文、回复和提及的精确上下文清空，发送期间继续编辑则保留。
- 频道面板增加纵向滚动，最小窗口高度仍可访问全部操作。
