# RelayCove V2 优化计划

Status: active backlog
Product: Windows MAUI personal MVP
Updated: 2026-08-26

## 已完成基线

Stage 31–38 已进入 `main`，其中 Stage 31–36 随 `v2.1.0` 发布，Stage 37–38 随 `v2.2.0` 发布。用户已在 Visual Studio/实际工程确认当前界面与交互。旧 Stage 日志已删除，历史以 Git 和 Release 为准。

本计划只保存仍有价值的后续方向，不要求一次性完成。每轮只接受用户明确提出的一个问题。

## 已完成的 V2 单点优化

- Windows 截图粘贴：原生 Composer 过去只同步纯文本，剪贴板位图不会进入附件链路。最终在 `PreviewKeyDown` 拦截含位图的 `Ctrl+V`，转为 PNG 草稿并显示缩略图；发送时图片使用 Zulip 内嵌图片 Markdown，普通文件仍使用文件链接。未采用把位图直接塞进 `RichEditBox` 的方案，避免绕开既有附件限制与上传失败语义。App 定向测试 324/324 通过，用户已在 Visual Studio 确认截图发送和显示正常。
- 私有群聊创建入口：register 的创建权限投影可能比服务器实际授权更保守，过去会在客户端提前禁用入口。最终允许所有已连接账号提交一次合规的私有群创建请求，由 Zulip 接口权威接受或拒绝；成员数量、活跃状态和零自动重试约束保持不变。未采用修改 Realm 权限或忽略服务器拒绝的方案。Core/App 定向测试通过，用户已确认入口行为。
- 文本发送即时反馈：过去 Composer 等待消息 POST 与权威历史确认后才清空，且 `Hidden` outbox 不投影，造成约 0.3 秒迟滞。最终在提交快照后立即清空输入框并投影本地消息，使用 client local ID 让服务器确认原地更新同一行；失败仍沿用既有显式恢复且绝不自动重发。初版 MAUI `Loaded/FadeTo` 会受虚拟化与默认容器过渡影响，已改为关闭默认新增过渡，并在真实可见容器上按“先插入、透明 100 ms、再用 140 ms 上移渐显”播放一次 WinUI 动画。Core 168/168、App 330/330 通过，最终动画由用户在 Visual Studio 确认。
- Windows 关闭到托盘：主窗口 `X` 过去直接销毁窗口和会话。现在取消普通关闭并隐藏主 HWND，使任务栏按钮消失而托盘与收信继续；内部离线预览仍可正常关闭。托盘右键提供唯一的“退出 RelayCove”，通过显式退出标记放行 `WM_CLOSE` 并复用既有停止/释放流程，不使用强制终止进程。App 335/335 通过，用户已确认交互。

## 后续顺序

### 1. 搜索正确性

- 本机与服务器的同一消息按真实 `messageId` 去重，本机当前状态优先。
- 同一会话的不同消息必须分别保留。
- 左侧会话搜索和右侧消息搜索使用独立取消通道。
- 消息命中行显示明确的“消息匹配”语义。

### 2. 写入结果确认

群名、公告、置顶和静音遇到超时、断线、5xx 或异常 2xx 时：

- 原写请求只发送一次。
- 最多进行一次权威读取。
- 结果区分“确认成功 / 服务器仍是原值 / 仍无法确认”。
- 账号、运行期或会话变化后禁止旧结果回填。

### 3. 群资料可靠性

- 新建群聊按需读取完整可见成员目录，并按 user ID 合并。
- 群成员头像、人数和名称搜索使用账号隔离的短期缓存。
- 邀请、移人或打开群设置后使对应缓存过期。
- 读取失败保留旧数据或群名首字回退，不阻塞聊天。

### 4. Windows 桌面体验

- 底部提示显示 `N 条新消息` / `99+ 条新消息`，无新消息但离底两页时仍显示“跳转到最新消息”。
- 会话列表补充键盘导航、可见焦点和 Narrator 描述。
- 账户菜单与新会话弹层关闭后返回触发按钮焦点。
- 字号设置覆盖左栏和聊天头，固定高度改为最小高度，避免 200% DPI 裁切。

### 5. 定向性能

- 消息正文解析增加账号/Realm/消息身份/raw 内容键控的有界缓存。
- 统一会话行用稳定 key 映射复用对象，减少重复扫描和集合 Reset。
- 不重写 Core reducer，不大型拆分 `ShellViewModel`，不改变 SQLite、未读和滚动状态机。

## 执行规则

- 逻辑问题运行最窄相关测试；UI 问题完成最小 App build 后由用户在 Visual Studio 确认。
- 每个完整代码批次按需要运行 Fast；正式发布候选才运行 Full。
- 不默认运行 Live、真实 Realm 写入、部署、tag、签名、安装器或干净 VM。
- `.verify/` 永远保留在本机，不清理、不暂存、不提交。
- 用户确认并明确要求后，才执行该问题的最小提交与推送。

## 不扩展范围

不恢复 Web 对齐、公开频道、命名话题、多人私信、后台 push、多账号、安装器或跨平台支持。
