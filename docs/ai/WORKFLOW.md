# 开发与证据工作流

本文件细化 [AGENTS](../../AGENTS.md)，不增加提交、发布或真实服务器写入权限。

## 每次修改

1. 检查分支与 `git status`，按 AI 索引阅读当前计划、状态和相关功能说明；保留无关改动。MAUI 默认直接在 main 处理一个问题。
2. 先核对入口、调用链、已有测试及用户反馈；把源码风险、复现结果和推测分别记录。
3. 做直接、最小的实现。功能变化同步更新 [功能说明](../FEATURES.md)；修复缺陷补回归测试。认证、协议、同步、数据、outbox 与打包变化需独立只读复核。
4. 运行与改动相称的验证。纯文档修改检查事实、相对链接和差异，不启动应用或自动跑 Full；一般逻辑修改运行定向编译与确定性测试，Fast/Full 的正式要求以 AGENTS 和产品计划为准。VS 占用输出时使用隔离构建目录。
5. 在交付用户验证前补齐[当月工作日志](../worklogs/README.md)，并更新 STATUS 的当前结论与限制；未执行的验证必须明确写“未运行/待验证”。
6. 视觉和原生交互由用户在 Visual Studio 确认。除非用户明确要求，Agent 不启动、移动、操作或截图用户窗口。交付说明列出改了什么和最短验证动作。
7. 用户确认后补记日志状态；得到提交/推送授权时只执行已确认范围的最小 Git 事务。

## 日志与功能说明的区别

- 功能说明描述“现在如何使用和实际如何工作”，不堆排查过程。
- 工作日志描述“这次解决了什么、改了哪里、怎样验证、还有什么没验证”。同一天同一问题只维护一条，按月保留。
- STATUS 只保留当前基线、实际验证和未关闭问题，不作为逐次工作日志。
- Release Notes 描述相对上一版的用户可见变化；不能把历史贡献再次算成本版新增。

## 验证与交付证据

记录命令、范围、结果，以及必要的本地证据路径。测试通过只覆盖测试断言；编译成功不等于 UI、剪贴板、Win10 故障设备或安装升级通过。用户确认只用于其实际反馈范围。日志不包含凭据、聊天原文或服务器响应。

纯提交/推送请求不附带额外打包、Live 或部署。正式发布按授权准备递增版本和构建号，完成 Full、必要复核、安装器和更新清单，并保持同一批载荷。提交后核对远端 HEAD/tag；发布后回读标题、说明、Latest 状态、全部资产的长度和 SHA-256。明确记录未运行的干净 VM、签名和真实 Realm 验证。
