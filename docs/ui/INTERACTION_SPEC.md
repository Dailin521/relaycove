# RelayCove Chat UI 交互规格

- 规格版本：1.13
- 对应基线：`chat-ui-v1`
- 状态：Current shared interaction contract；`chat-ui-v1` 仅保持冻结初始基线
- 最后更新：2026-08-21

## 1. 目的与边界

本文把已确认界面中的操作转成可测试产品行为。Stage 24 以前默认由 RelayCove.Web 先实现、MAUI 用原生 XAML/ViewModel 复刻；自 Stage 25 的 2026-08-21 决策起，MAUI 是唯一继续开发和交付的产品客户端。旧 Web 条款只保留历史语境，不再构成对齐要求。

冻结 HTML 决定初始外观参考，正式 RelayCove.Web 已验收行为与本文决定当前交互语义；产品范围、安全或协议问题仍以根计划和 Zulip 12.1 证据为准。现有 Zulip 官方 Web 保留不动，两端均直接连接同一 Realm；任何 Web 进度都不能替代 MAUI 人工登录或干净 VM 门禁。

### 1.1 Stage 25 MAUI-first 覆盖规则

本节在冲突处覆盖本文后续面向 MAUI 的旧频道/话题/群组私信描述；那些旧描述继续作为 `RelayCove.Web` 与 Stage 24 历史契约，不改写冻结的 `chat-ui-v1`。

- MAUI 左栏只有一份会话时间线：一对一/self-DM，以及已订阅、活动、私有、非 Web 公开、`topics_policy=empty_topic_only` 的频道群聊。公开频道、Web-public、旧多话题私有频道和 group-DM 不进入列表、列表搜索或消息搜索结果。
- 群聊内部键固定为 `ChannelTopic(channelId, "")`；UI 不显示 `#`、话题、话题菜单、新话题或公开频道浏览入口。外部改变隐私/话题策略后立即关闭当前会话并禁止发送，但不删除服务器历史或主动清理因资格变化而隐藏的旧缓存。
- 会话按置顶优先、最新消息时间倒序、规范键稳定排序；群头像用最多四名成员按用户 ID 排序的 2×2 拼图，成员未知时回退群名首字。
- `+` 只分流“发起私聊”和“新建群聊”。私聊只选一人；群聊必须填写群名并选择至少两名其他活跃成员。register 权限无法完整解析时群聊入口禁用并显示原因。
- 新群通过一次非重试创建请求提交全部初始成员、私有/非 Web 公开、共享历史、空话题策略、无创建公告以及创建者独占的 administer/add/remove-subscriber 权限。创建、邀请、移人、转让、解散和发送结果不确定时不得自动重试，必须读取权威状态并要求用户核对。
- 群设置显示成员、群名、公告、本机备注、查找消息、免打扰、置顶、清本机聊天缓存和退出。只有三项管理权限明确为同一直接成员时才识别 RelayCove 群主；群主额外可改名、编辑公告、邀请、移人、转让和解散，复杂外部权限结构失败关闭到个人设置。
- 转让先原子更新并确认三项权限，再让旧群主退出；解散先移除并确认其他成员，再让群主退出。清聊天记录只清当前账号、当前规范会话的本机消息、话题摘要和未读缓存，不删除服务器消息、订阅或凭据。

## 2. 核心术语和信息架构

| UI 名称 | 领域含义 | 规则 |
|---|---|---|
| 工作区 | 一个 Zulip Realm | 当前共享功能矩阵只有一个活动账号，不提供多工作区切换 |
| 频道 | Zulip channel/subscription | Web 沿用频道语义；MAUI Stage 25 只把合格私有空话题频道呈现为群聊 |
| 话题 | Zulip topic | 消息会话的真实键是 `ChannelTopic(channelId, topic)` |
| 私信 | 1:1、群组或 self-DM | Web 可保留三类；MAUI Stage 25 只投影 1:1/self-DM |
| 会话 | 一个规范消息键 | MAUI Stage 25 仅接受一对一/self-DM 与合格 `ChannelTopic(id, "")`；旧 generation 不能覆盖新会话 |

RelayCove.Web 仍可按“频道”和“私信”分组，并保持真实话题身份。MAUI Stage 25 不分组、不混入命名话题，只把明确声明 `empty_topic_only` 的私有频道以单群聊呈现。

## 3. 桌面窗口和总体布局

### 3.1 标题栏

- MAUI 左侧以当前用户头像作为账号入口，随后显示 RelayCove 标题和当前工作区名称；不再显示单独的 `R` 标识。头像通过账号隔离的受控媒体加载，缺失或失败时回退姓名首字母。
- MAUI 右侧产品动作依次包含设置、主题和置顶，随后是系统最小化、最大化/还原、关闭。设置仅在已进入主界面后显示，再次点击可从设置页返回消息区。
- 置顶是可切换状态，必须有可感知的 pressed 状态。
- 最大化按钮在最大化后执行“还原”；窗口关闭遵循应用生命周期，不伪造为注销。
- Windows 特有窗口行为放在 App/Platforms/Windows，不进入 Core。

### 3.2 列布局

MAUI 主界面从左到右为会话列表和聊天区，不再渲染独立主导航栏。可折叠的会话设置面板只在聊天头部显式打开后临时占用右侧空间，不算常驻主列。RelayCove.Web 的现有导航布局不在本轮修改范围内。

- 1440×900 是视觉基准。
- 1024×768 必须可用，详情面板默认收起，聊天区不能出现横向滚动。
- RelayCove.Web 在低于 720 px 时切换为单栏列表/聊天；该浏览器响应式证据不属于 MAUI Windows 首轮验收门禁。
- 会话列表宽度可作为设备偏好保存，不进入账号业务状态；会话设置不自动打开，只由当前聊天头部的设置按钮打开。

## 4. 全局入口

### 4.1 MAUI 主界面

MAUI 不显示头像/消息/联系人/已保存/设置组成的左侧栏。消息区就是默认主界面；联系人和已保存不提供原生主壳层入口。当前用户头像显示在左上标题栏；点击后在主内容左上打开包含身份、账户设置与注销的账号菜单。当前共享能力未实现 presence；没有权威状态时不得伪造“在线”。

### 4.2 设置入口

MAUI 设置按钮位于窗口右上产品标题栏。点击后打开独立设置视图；设置激活时按钮保持可感知选中状态，再次点击返回频道与私信会话区。此入口不触发 Realm 写入。

### 4.3 未读状态

- 红点颜色使用危险/注意语义红色，不能只靠颜色表达，辅助名称包含未读数量。
- 会话红点取当前会话的权威未读数；频道汇总必须按频道内话题准确归并。
- 会话列表按各会话的权威未读数显示状态；MAUI 不再额外汇总一个主导航红点。
- 如果服务端声明未读数据被截断，UI 显示“有未读”而不是伪造精确总数。
- 两端都不在点击行时乐观扣减；MAUI 只有 `MarkReadAsync` 成功且 `IClientSession` 发布新状态后才刷新，Web 只有当前 narrow 的 flags 请求成功且 reducer 发布新状态后才刷新。
- 当前用户发送的消息无论 history/register/realtime 是否省略 `read` flag，都按已读投影，不生成会话红点、主导航红点或未读分割线。
- 实时消息、已读 flag、移动、删除和撤权事件都必须触发同一个投影更新，禁止另外维护一套 UI 计数。

## 5. 会话列表

### 5.1 顶部工具

中栏顶部只保留：

- 一个全局搜索框；
- 一个 `+` 新建按钮。

不在此处增加筛选条、工具条或多余图标。MAUI Stage 25 的 `+` 只包含一人私聊与命名私有群聊；Web 的历史群组私信/频道话题入口不在本轮改动。

### 5.2 Web/Stage 24 历史频道组（MAUI Stage 25 不适用）

- App 频道区显示紧凑频道主行：彩色 `#`、频道名、未读数和行内动作；不在频道行显示最近话题/摘要或时间。展开的话题直接缩进在所属频道下，单话题频道也必须可见；选中话题提供非颜色的勾选/选中状态。
- 一次只展开一个频道，且展开状态只属于本次运行。首次点击频道展开并打开本次运行记住的话题，否则打开最新话题；再次点击仅收起话题，当前聊天不变。切换到另一频道取消旧加载并收起前一频道；切换私信也收起频道话题。
- 频道行在选中、悬停或其菜单打开时显示 `+` 与更多按钮。`+` 复用新建频道话题界面并锁定该行频道；打开和取消都不产生 Realm 写入，只有随后发送首条消息才走既有发送语义。
- 更多菜单按官方频道动作模板分段，锚定在所点行且始终按该行频道 ID：带彩色 `#` 的频道标题；动态“将所有消息标记为已读/未读”、前往频道订阅、前往话题列表、复制链接；频道设置、置顶/取消置顶、静音/取消静音、退出；修改颜色。频道设置直接打开以触发行频道 ID 为目标的独立覆盖页，不先改变聊天会话；退出继续二次确认。菜单支持外点、`Escape`、键盘焦点以及关闭后返回触发按钮。
- 话题行使用频道 ID + 原始话题名作为稳定目标。选中、悬停或菜单打开时显示个人通知状态、未读数和更多按钮；更多按钮不得触发行激活。
- 话题菜单按通知策略、已读/复制、整话题管理三组排列并锚定触发行。外点和 `Escape` 先关闭移动/解决/删除子层，再关闭菜单；最终关闭后焦点返回原更多按钮。
- 尚无消息锚点的话题不得发起整话题读写。个人通知/已读操作要求已认证用户和活动订阅；移动/解决权限未知时失败关闭到已确认组织管理员，删除只对已确认组织管理员开放且必须二次确认。任何 `complete=false` 删除结果都不得自动重试。
- 复制话题链接使用 Zulip narrow hash 编码；移动/解决先读取最早消息再执行一次 `change_all`。仅幂等的整话题标记已读允许按服务端游标分页。
- 前往话题列表展开并激活所点频道；复制链接写入本机剪贴板。频道级读/未读标记、频道订阅页和颜色修改尚无 Core/协议能力，保留官方位置但只给出明确的“未接通、未执行 Realm 操作”提示，绝不伪造成功或写入。
- 撤权、取消订阅或频道归档事件到达后立即从列表移除，并清理选中状态。
- 当前频道被移除时回到安全的下一个会话或空状态。

### 5.3 Web/Stage 24 历史私信组（MAUI Stage 25 不适用）

- 私信组与频道组独立折叠，使用同一 `aria-expanded`/键盘/搜索临时展开语义。
- 列出当前客户端可靠获知的工作区成员和既有 DM；若服务器数据不完整，界面不得声称“全部成员”。
- 每行显示头像或简单图标、姓名、最近摘要、时间和未读状态。
- 摘要、时间、头像色调和媒体 source 以稳定会话键/用户 ID 投影；仅刷新消息窗口不得重建头像或先清空摘要。
- self-DM 明确显示“自己”。群组私信显示参与者摘要，不折叠成虚假的单人身份。

### 5.4 Web 群组私信（MAUI Stage 25 隐藏）

- `+ -> 新建群组私信` 打开成员多选；至少选择两名其他成员时才形成群组 DM，选择一名成员应回到普通 1:1 私信流程。
- 标题由规范参与者集合稳定生成，不伪造 Zulip 不存在的持久群名称；成员过多时显示前若干姓名和总人数。
- `DirectMessage(sorted otherUserIds)` 是会话身份。改变收件人集合会打开/创建另一个会话，不能就地篡改旧会话的参与者。
- 列表摘要、未读、分页、草稿、outbox 和发送恢复规则与 1:1 DM 相同。
- 详情面板在有可靠用户资料时列出参与者；群组 DM 不显示频道管理员动作，也不自动弹出 `@` 候选。
- 发送必须使用规范参与者 ID，不能从截断后的显示标题反推收件人。

## 6. 全局搜索

### 6.1 打开与关闭

- MAUI Stage 25 会话栏输入只即时筛选统一会话与已加载的合格消息；服务器消息搜索也必须过滤掉公开/旧话题频道和 group-DM。Web 保留既有频道、话题、私信与成员索引范围。
- `Escape` 关闭；点击面板外关闭；关闭不切换当前会话。
- `ArrowUp`/`ArrowDown` 移动当前项，`Enter` 打开结果。

### 6.2 匹配规则

- 支持大小写不敏感的连续部分匹配，不要求前缀或完整词。
- 单个汉字、字母或数字均可触发匹配；不得因为查询太短而静默拒绝。
- 结果顺序固定为：私信、频道、成员。每组内部的最终排序由实现计划明确，且必须稳定。
- 匹配字符使用绿色强调，同时保留足够的非颜色对比。

### 6.3 索引字段

| 索引 | 包含 | 明确排除 |
|---|---|---|
| 私信元数据 | 1:1/self-DM 姓名，群组 DM 的全部规范参与者姓名/ID，可靠角色/状态 | 行时间、未读数字 |
| 频道元数据 | 显示名、频道名、话题、可靠成员名 | 行时间、置顶图标、未读数字 |
| 成员元数据 | 姓名、角色、可靠状态、规范 ID | 最后活跃时间 |
| 消息内容 | 真实聊天正文、附件文件名 | 消息时间、日期分割线、未读分割线、发送状态文案、系统布局文本 |

当命中消息正文时显示 `消息：…`；命中附件名时显示 `附件：…`。时间文本即使与查询完全相等也不能产生消息结果。

### 6.4 在线与离线语义

Stage 22W 当前没有正式全局/服务端搜索数据契约；本地 fixture 和正式页的当前会话列表过滤都不是消息搜索能力。后续正式搜索必须明确结果来源：

- 在线：允许组合 Zulip 搜索和本地会话/成员索引。
- 离线：只查账号隔离缓存，并显示“结果可能不完整”。
- 查询变更时取消旧请求，并用请求序号拒绝过期结果覆盖。

## 7. 聊天头部与详情面板

### 7.1 聊天头部

- MAUI Stage 25 群聊显示群名和权威成员数，不显示 `#` 或话题；1:1/self-DM 显示成员名。Web 保留频道话题与群组 DM 标题语义。
- 右侧只保留搜索与省略号设置按钮；不再放置独立信息按钮或头部话题更多按钮。话题操作仍从所属话题行的更多菜单进入。

### 7.2 详情面板

- MAUI Stage 25 群设置按第 1.1 节展示成员、群名、公告、本机备注、搜索、免打扰、置顶、清缓存与退出；成员列表不可用不影响已权威确认的普通成员退出，但频道详情/权限本体不可用时退出与管理均失败关闭。
- 一对一私聊设置只显示对方头像、消息免打扰和置顶聊天；两项均按账号和规范私聊键保存在本机，不伪造 Zulip 用户静音或系统通知能力。本轮不增加多人私信设置或成员管理。
- “清聊天记录”只清当前账号下当前规范会话的本机 SQLite 消息、对应话题摘要与未读缓存，不删除服务器消息、订阅或凭据。MAUI 群聊只允许空话题规范键；清除时取消旧历史加载，重新进入后从 Zulip 再同步。
- 面板可折叠；收起只影响布局，不取消当前会话。切换会话关闭设置并取消旧资料加载。

当前共享契约仍没有通用的 presence 或共同频道投影。Stage 23 已实现 MAUI 服务器搜索、当前账号 saved 聚合页和普通用户频道自助；Stage 24.10 的频道设置以 `GET /streams/{id}/members` 的频道成员 ID 和 `GET /users` 的当前账号可见组织用户目录建立临时权威投影，不得用聊天会话里碰巧加载到的用户猜测频道成员或管理权限。

### 7.3 频道权限矩阵

| 动作 | 频道管理员 | 普通成员 | 生产约束 |
|---|---:|---:|---|
| 重命名频道 | 可见且可执行 | 不可见/禁用 | 提交时仍由服务器复核 |
| 删除频道 | 可见且需危险确认 | 不可见/禁用 | 必须先确认 Zulip 是删除、归档还是停用语义；不伪造永久删除 |
| 移出成员 | 可见且需确认 | 不可见/禁用 | 403 时刷新 capability 并提示权限变化 |
| 主动退出频道 | 可见 | 可见 | 成功后从导航移除并清理选中状态 |

生产代码使用服务器 capability，而不是只判断本地布尔值。Stage 22W 已实现“当前用户主动退出频道”：二次确认后按真实订阅名提交，成功或服务端确认已退订时执行既有撤权清理；结果未知不自动重试。Stage 24.10 接通名称、说明、文件夹、组织管理员归档和成员管理；成员添加与移除分别使用独立 capability，写前按频道 ID 重新读取权威频道名称，非幂等请求不自动重试。

### 7.4 频道设置覆盖页

- 设置页标题为“频道”。宽窗口为频道目录/详情双栏，窄窗口为目录→详情并提供返回；两种宽度共享同一详情实现。界面沿用 RelayCove 的现代极简 token、留白、浅边框和圆角，不复制 Zulip 旧版密集灰色皮肤。
- 左栏提供已订阅/可用/全部、搜索、未归档/已归档/全部以及名称/订阅人数/活跃度排序；这些能力在窄屏同样可达。频道行显示订阅状态、隐私/颜色、名称、说明、订阅人数和周消息量，并明确当前选中行。
- 右栏包含 General、个人、订阅者和权限。Personal 只在当前用户已订阅且频道未归档时可用；Subscribers 只在权威成员读取能力存在时可用；权限不完整或匿名自定义组不可安全编辑时保持只读。
- General 显示隐私、名称、说明、创建者/日期/ID、频道文件夹和按需读取的频道邮件地址。个人页只常驻显示当前色块与“修改颜色”；打开后在入口旁锚定小型弹层，以频道标题实时预览、官方 4×6/24 色色盘和可展开的 Windows 原生自定义取色器编辑草稿。弹层高度受限且内容可滚动；色盘可键盘操作，只有顶部确认才写服务器，外点或 `Escape` 恢复原色并返回入口焦点。静音、置顶和各通知状态继续遵循服务器值；`null` 表示继承组织默认，客户端不得伪造不受 API 支持的 reset 写入。
- 订阅者页同时读取频道成员真实 ID、当前账号可访问的组织用户目录及 `GET /users/me/subscriptions` 的当前用户订阅状态，全部完成且目标仍当前后才投影。不得再用 `_session.State.Subscriptions` 覆盖该设置快照的订阅结果。已订阅者不受候选搜索影响；候选仅包含活跃的非成员，并支持姓名/邮箱搜索。任一成员 ID 缺少权威用户映射时整页失败关闭。添加和移除分别受 `can_add_subscribers_group` / `can_remove_subscribers_group` 与组织管理员规则控制；私有频道的内容访问必须使用该权威订阅状态。移除必须显示成员姓名并二次确认，失败留在确认层且不自动重试，添加可明确选择是否发送新订阅通知。
- 权限页显示公开/私有/Web 公开、历史可见性、默认频道、话题策略、消息保留和全部已建模 group-setting。内容访问类设置要求频道管理权和实际内容访问；只有元数据管理权时失败关闭。命名组必须携带精确 old/new 提交；匿名 `{direct_members,direct_subgroups}` 只读且不得静默替换。Web 公开和默认频道只允许组织管理员修改。
- 设置页顶部的 `+` 创建频道，与左侧导航频道行的“新建话题”不是同一入口。创建频道支持公开、私有和 Web 公开；公开类频道强制共享历史，私有频道可明确选择历史是否对后续订阅者可见。
- 每次打开、选频道及确认写入后重新读取权威数据；关闭、换频道、换页和刷新取消过期请求。所有写入捕获设置页选中的频道 ID，服务器成功后才刷新；PATCH/POST/DELETE 不自动重试。
- 订阅/退出按服务端能力显示；归档/取消归档只对组织管理员开放，两者都使用二次确认。前往频道关闭覆盖页并打开目标频道；覆盖页和子弹窗支持外点、`Escape` 分层关闭和焦点返回。

## 8. 消息列表

### 8.1 正常消息

- 展示头像、发送者、时间和 raw Markdown 文本。
- 头像优先使用 Zulip `avatar_url`；同 Realm 公开 `/user_avatars/` 与 `/static/generated/avatars/` 可在无凭据、无 referrer 条件下直接显示。受保护路径只在浏览器同源时通过认证 Blob 读取；本地跨源 `/avatar/{user_id}` 不绕过 CORS，回退稳定首字母/Bot 图标。任何外站头像均拒绝。
- 自己的消息右对齐，其他消息左对齐；颜色不能作为唯一身份区分。
- 当前 Web 按已加载消息直接渲染，初次进入从网络取数，不声明虚拟化或持久消息缓存；后续引入这些能力时仍须保持本规格的结构、焦点与撤权语义。
- 当前 Web 通过明确入口加载每页 50 条历史；滚动阈值自动触发、长列表虚拟化和跨页视觉锚点保持仍是后续性能切片，不得误报已完成。

### 8.2 引用、反应和附件

- 引用回复在气泡内显示发送者和完整 raw Markdown 摘录；草稿使用发送者标识、原消息永久链接与 fenced `quote`。连续多段引用各自显示为独立引用卡，不能只识别第一段而把后续围栏泄漏成正文。正文、图片和其他附件链接都必须保留，不能从已渲染图片占位或 HTML 反推。点击定位属于后续能力。
- Windows Composer 插入引用后，光标必须位于结束围栏及保留空行之后；LF/CRLF 转换不得把光标移动到围栏内部。对旧版 RelayCove 已发出的、回复文字紧贴结束围栏两侧的内容，原生投影应恢复引用与普通回复的边界，不修改服务器 raw Markdown。
- 反应只从历史 `reactions` 和 realtime `reaction` event 投影，按 `reaction_type + emoji_code` 聚合。选择器添加或移除当前用户的 reaction 时必须提交服务器提供/内置的完整 `emoji_name`、`emoji_code`、`reaction_type`，不伪造计数。
- 图片消息显示受控缩略图和文件名；点击打开遮罩预览，`Escape`、关闭按钮或点击遮罩退出。
- 同 Realm `/user_uploads/` 的 PNG/JPEG/WebP/GIF/AVIF Markdown 链接可生成图片预览；同 Realm SVG 和其他文件只生成非活动文件卡片。跨 Realm、`data:`、`javascript:` 与异常链接继续按 raw Markdown 文本显示。
- 私有上传先通过带 Basic 的 `GET /api/v1/user_uploads/{path}` 换取短期 URL，再立即读取为内存 Blob；短期 URL 和 API Key 都不进入图片 DOM。离开会话、注销或撤销最后引用时 abort 请求并 revoke object URL。
- 图片下载使用已经授权读取的 Blob，不重新暴露远端地址。加载失败显示文件名、明确失败状态和手动重试。
- 每条消息最多生成 4 个图片预览，全局同时最多读取 4 个 Realm 媒体，当前页面缓存 Blob 总量最多 64 MiB。超额图片链接继续保留为 raw Markdown，不静默丢弃。
- 同 Realm `/user_uploads/` 的非图片 Markdown 链接显示为文件卡片。点击时先以 Basic 获取短期 URL，再以无 Authorization、无 referrer、禁重定向请求读取有大小上限的 Blob；SVG、HTML、PDF、Office 和未知文件均不得内嵌为活动内容。

### 8.3 消息操作菜单

- 鼠标右键、键盘 `Shift+F10`/菜单键，以及触屏可见的“更多”按钮打开同一菜单。
- 每条消息在悬停/键盘聚焦时显示“引用、复制、更多”快捷工具；触屏布局保持可见。“更多”与右键/菜单键打开同一完整菜单。
- 完整菜单只展示确实已接通的动作：reaction、收藏/取消收藏、引用到输入框、复制 raw Markdown 正文/链接/ID、在官方 Zulip Web 打开；本人消息额外显示编辑和永久删除。
- “引用回复”插入带发送者的 Zulip Markdown 引用，不自动发送；现有草稿保留，焦点进入输入框。
- 菜单支持上下键、`Home`/`End`、`Enter`，`Escape` 或点击外部关闭；非回复关闭后焦点回到触发消息/按钮。
- 编辑使用当前 raw Markdown 的 UTF-8 SHA-256 作为 `prev_content_sha256`；冲突保留草稿。删除必须经过“永久且不可撤销”确认。收藏是当前账号私有 `starred` flag。
- 同一消息的写操作串行且提交中禁用重复动作；HTTP 2xx 后更新本地投影，后续 event 幂等收敛。网络、5xx 或超时属于结果未知，显示明确状态且绝不自动重试/补偿；401 立即重新认证并清除本地凭据。
- 标未读仍是未实现的独立能力；未接通 capability/权限/失败语义前不得显示假动作。服务器始终是编辑/删除权限和时间窗的最终裁决者。

### 8.4 分割线

- 日期分割线为中性色，仅用于阅读定位。
- 未读分割线为红色，位置由权威未读状态决定。
- 最新页成功且仍为当前 generation 后可自动标读。当前可见会话收到他人实时新消息时，只有窗口激活、聊天面板可见、没有遮罩、当前 history 成功且消息列表在事件到达前已位于底部，才可再发起标读；realtime follow-scroll 的后续 WinUI 确认不得阻塞该请求。手动跳转或激活滚动仍须列表确认。
- 自动标读必须携带预期会话并在 session command gate 内重新核对；切换会话、窗口失焦、窄屏返回会话列表、打开设置/遮罩或离开底部都不得把其他会话标为已读。标读失败保留未读，不得把已成功加载的消息误报为历史失败。
- 消息未读线、会话红点和主导航红点只在服务器成功且 Core 发布 `read` flags 后收敛，App 不乐观清零。
- 两种分割线都不是消息，不进入消息搜索、复制或发送者统计。

### 8.5 状态矩阵

| 状态 | 表现 | 可执行行为 |
|---|---|---|
| 正常 | 消息列表和输入区可用 | 发送、分页、标已读 |
| 正在加载 | 骨架和“正在加载聊天记录” | 可取消旧加载；不显示虚假空会话 |
| 空会话 | 空状态和发送第一条消息提示 | 输入并发送 |
| 离线 | 明确离线提示，缓存消息仍可读 | 保留草稿；发送不发起网络请求 |
| Hidden | 本地回声在 500 ms 窗口内隐藏 | 无需提示 |
| Waiting | 显示正在等待服务器事件 | 不允许自动重复发送 |
| WaitExpired | 显示结果不确定 | 恢复正文，提示手动重试可能重复 |
| Failed | 红色失败提示和恢复入口 | 恢复正文后由用户显式再次发送 |
| MessageMutation | 消息行显示 reaction/edit/delete/star 提交、未知或失败状态 | 同消息写入口锁定；未知结果只能刷新确认，禁止自动重试 |
| ReauthRequired/Locked | 聊天内容锁定并进入重新认证 | 不允许绕过凭据查看缓存 |

## 9. 输入区

### 9.1 布局与工具

- 输入区固定在聊天区底部，消息区占用剩余高度。
- 工具栏当前只保留表情和上传；发送按钮位于右侧。表情按钮打开本地 Unicode 选择器，在当前光标/选区插入文本并恢复输入焦点；它不是消息 reaction 写入。
- 文本框支持多行；Windows 原生 Composer 使用普通 `Enter` 发送、`Ctrl+Enter` 换行。IME 组合输入期间 Enter 只交给输入法，不触发发送；发送命令不可执行时 Enter 不创建空消息。
- Windows Composer 获得焦点且没有文本选区时，使用系统原生插入光标并按用户的系统闪烁周期持续闪烁；失焦、存在选区或 IME 正在组合时由系统文本控件处理可见性。应用不得修改系统全局光标设置，也不得叠加第二条应用光标。
- 每个会话保留独立草稿；切换回来恢复正文和待发送预览。
- 群组私信发送使用选中 `DirectMessage` 的完整规范参与者集合；self-DM 使用当前用户 ID，二者都不得从界面标题解析收件人。
- 发送请求持有独立提交快照/版本。成功确认只清除与该提交匹配的目标会话草稿，不能清除发送后新输入；发送中切换会话也不能把已确认消息重新恢复为草稿。

### 9.2 高度调整

- Composer 顶部边框及其上下附近是窄拖拽热区；没有单独的灰色水平把手，指针光标为上下调整。
- 向上拖动增高，向下拖动降低；Windows 原生范围为 128–300 px。128 px 保留 40 px 工具栏和 64 px 多行编辑区，避免文本溢出。
- 拖动时聊天消息区实时让出空间，底部边缘保持固定。
- 拖柄获得焦点时，`ArrowUp`/`ArrowDown` 每次调整 16 px，`Home` 最小，`End` 最大。
- 窗口收窄后重新 clamp，输入区不得覆盖标题栏或发送工具。
- MAUI Windows 使用原生 pointer capture；Released、Canceled、CaptureLost 与失焦都必须结束拖动。附件出现只提升到最低可用高度，不覆盖用户已选择的更大高度。

### 9.3 消息视口

- 距离真实滚动底部不超过 96 DIP 时，新消息自动跟随；超过 96 DIP 时保持可见锚点，不因追加或重新测量抢走阅读位置。
- 当真实底部距离严格超过当前消息视口高度的两倍时，即使没有新到消息，也在消息区底部居中显示“跳转到最新消息”浮动按钮；恰好两倍时不显示。离底期间收到新消息也复用同一入口。点击后发起独立的手动 latest-scroll 请求，原生列表确认到达最新位置后隐藏按钮并清除本地新消息计数。
- 向上分页和消息高度变化以首个可见消息 ID 与顶部 DIP 偏移恢复；重复刷新但没有新消息时不得抢滚动。
- 首次进入、切换或重新进入会话时，每一次访问都必须产生独立的“定位到最新消息”意图；即使会话键、history generation 和最新消息 ID 与上一次完全相同，也不得复用上一次已完成的滚动确认。
- MAUI `CollectionView` 的目标容器已实现不等于最终 extent 已稳定。会话激活应在目标消息实现并连续确认底部布局稳定后再展示消息列表，避免先显示中段、顶部或旧绝对偏移再跳到底部。
- 会话激活、近底实时跟随和向上分页锚点是三种不同语义：激活可以短暂隐藏列表完成定位；实时发送/追加保持当前列表可见且只跟随最新；向上分页必须保护首个可见消息及 DIP 偏移。不得用全局 `LayoutUpdated → ChangeView(bottom)` 同时处理三者。

### 9.4 `@` 成员

- 只有频道话题会话在光标前形成有效 `@query` 时显示候选。
- 私信、群组私信和 self-DM 都不自动弹候选；手工 `@` 仍是普通文本。
- 候选只可标为“频道成员”或“工作区成员”中的一种，必须与实际数据源一致。
- 支持部分匹配、上下键、`Enter`/`Tab` 插入和 `Escape` 关闭。
- Zulip mention Markdown 格式必须按固定 12.1 协议证据实现，不能只插入显示名。

### 9.4 附件选择与发送

- 点击上传打开支持多选的系统文件选择器；也可把本地文件拖到输入区。只处理 `DataTransfer.files`，拒绝远程 URL/HTML 拖入并阻止浏览器导航。取消或拒绝不改变正文和既有附件。
- 支持任意文件类型，每条消息最多 10 个；拒绝空文件、控制字符/过长文件名、超过 register `max_file_upload_size_mib` 的单文件和超过产品总预算的组合。MIME/扩展名只决定展示，不作为上传信任依据。
- PNG/JPEG/WebP/GIF/AVIF 显示本地 Blob 缩略图；其他类型只显示文件图标、名称、大小和移除按钮，不生成活动预览。每个会话独立保存附件草稿。
- 上传按草稿顺序逐个执行 `POST /api/v1/user_uploads` multipart `filename`；服务端返回的 `filename` 必须清洗并按 Markdown label 转义，URL 必须保持同 Realm。所有上传确认后，正文和全部链接只进入一次消息 POST。
- 上传和消息 POST 是两个明确步骤，二者都不自动重试。若上传已确认而消息 POST 失败/不确定，保留已上传引用以供用户明确重试，不再次自动上传。
- 用户确认注销时，先同步取消仍在进行的上传、失效本次提交并释放图片草稿 Blob URL，再停止会话和清除凭据；即使底层 adapter 在取消后异常返回成功，也不得继续消息 POST。

## 10. 设置

设置页必须在页面内部提供明确的“返回聊天”入口，不能只依赖再次点击标题栏齿轮。宽窗口位于左侧设置目录顶部；窄窗口位于顶部横向分类栏首项。返回只切回当前消息区，不改变已选会话或触发 Realm 请求。

| 页面 | 预期行为 | 范围说明 |
|---|---|---|
| 通用 | 启动行为、语言等设备偏好 | 只保存非敏感配置 |
| 外观 | 主题、密度、字号、列表宽度 | 立即预览；提供恢复默认 |
| 通知 | 展示说明或能力门 | 当前共享能力不实现系统通知 |
| 存储 | 显示缓存说明、清除当前账号缓存 | 精确目录校验后才删除 |
| 账户 | Realm、邮箱、注销 | 不显示或记录 API key/密码 |

清缓存和注销必须二次确认。注销先停止事件循环，再删除凭据并锁定缓存；清缓存不删除服务端消息。

Web 账户策略与 MAUI 凭据介质不同：Web 默认勾选“记住登录”，可把 Realm、邮箱和 API Key 写入当前浏览器 local storage；取消勾选时只写 session storage；注销清除两者。MAUI 继续使用 SecureStorage。两端均不得在设置页展示 API Key，也不得把它写入 URL、日志、异常或测试快照。

## 11. 无障碍与键盘

- 所有图标按钮都有可读名称；状态按钮暴露 pressed/expanded/selected。
- 焦点样式在浅色和深色主题均清晰，不能只依赖鼠标 hover。
- 弹层打开后键盘可完整操作；关闭后焦点回到触发控件。
- 红点、在线/离线、失败和高亮均提供文字或辅助名称。
- 最低检查包含 200% Windows 缩放、键盘单独操作和高对比主题可读性。

## 12. 验收场景

1. Given 主导航总未读为 8，When 依次确认未读 5、2、1 的会话，Then 总数按权威状态变为 3、1、0，最后隐藏红点。
2. Given 全局搜索打开，When 输入 `好`，Then 先显示私信匹配，再显示频道匹配，命中字为绿色。
3. Given 全局搜索打开，When 输入 `09:12`，Then 不因消息时间产生结果。
4. Given 消息含附件 `relaycove-team-avatars.jpg`，When 输入部分文件名，Then 结果显示 `附件：…`。
5. Given 输入区默认 128 px，When 向上拖动或按 `ArrowUp`，Then 输入区增高且消息区缩小，范围不超出 128–300 px。
6. Given 当前是频道话题，When 在光标处输入 `@ma`，Then 只列出允许的数据源内匹配成员；切换私信后候选关闭。
7. Given 选择图片和普通文件，When 文件进入草稿，Then 图片显示安全缩略图、普通文件只显示文件卡片；逐项移除后正文保留。
8. Given 发送结果为 WaitExpired，When 用户选择恢复，Then 正文回到输入框并明确提示再次发送可能重复。
9. Given 当前用户没有频道管理 capability，When 打开详情，Then 不提供重命名、删除或踢人动作。
10. Given 窗口为 1024×768，When 打开主会话，Then 列表、聊天和输入区均可操作且无横向滚动。
11. Given Web 选择两名其他成员创建群组私信，When 发送文本并切换离开再返回，Then 会话键、参与者标题、草稿、未读和 outbox 均保持在同一规范参与者集合；MAUI Stage 25 不提供此入口。
12. Given 尚未启用频道成员/已保存读取能力门，When 打开详情或主导航，Then 不展示推测成员、共同频道、presence、capability 或虚假的已保存结果。
13. Given 消息正在发送，When 用户切到其他会话并在成功确认后返回，Then 目标消息只出现一次、原提交不回到输入框；若发送后已有新输入，新输入仍保留。
14. Given Web 使用 fake HTTP，When 登录，Then 先无凭据请求 `/server_settings`，再只在 `/fetch_api_key` form body 中发送密码。
15. Given Web 已取得 API Key，When 构造后续 Zulip 请求，Then 使用邮箱与 API Key 的 HTTP Basic，且 Key 不出现在 URL、日志、UI 或测试快照。
16. Given 默认记住登录，When 刷新 Web，Then 从 local storage 恢复 Realm、邮箱和 API Key；取消记住时只在当前 session 恢复。
17. Given Web 已登录，When 用户确认注销，Then local storage 与 session storage 中的 RelayCove 凭据均被清除。
18. Given Web 已取得完整会话，When register 成功，Then 订阅、用户、近期私信和未读作为一个快照发布，queue/cursor 不进入持久存储或 UI。
19. Given 当前选择频道话题或 DM，When 请求最新/更早历史，Then 使用规范 narrow 和 50 条分页；快速切换会话后旧响应不能覆盖新会话。
20. Given 当前存在未读消息，When Web 调用标已读，Then 只有服务器成功后才减少红点；失败时投影保持不变。
21. Given 文本发送 HTTP 结果模糊，When 进入 Failed/WaitExpired，Then 客户端不自动重发，正文可恢复且明确提示再次发送可能重复。
22. Given event queue 返回 `BAD_EVENT_QUEUE_ID` 或 restart，When Web 恢复，Then 丢弃旧 queue/cursor、重新 register，并不复用过期队列。
23. Given subscription/stream 撤权事件到达，When reducer 发布新状态，Then 同频道导航、话题、消息、未读和当前选择一并清除。
24. Given 一条正式消息，When 鼠标右键、触屏更多按钮或 `Shift+F10` 打开菜单，Then 只显示已实现动作；上下键可导航，`Escape`/外点关闭并恢复焦点，整个过程零 Zulip 写请求。
25. Given Zulip 用户有同 Realm 头像或仅有 user ID，When 列表、联系人和消息显示该用户，Then 头像通过受控 Blob 加载；失败时回退一致且 API Key 不在 URL、DOM、日志或截图。
26. Given 消息含同 Realm 图片和普通附件链接，When 用户打开它们，Then 图片进入受控预览；普通附件只在点击后经临时授权 URL 下载 Blob，不进入 `img/iframe/object`；不安全 URL 仍显示 raw Markdown。
27. Given Composer 已有正文，When 多选或拖入有效附件再移除，Then 正文保持不变；重新添加并明确发送时每个文件只上传一次，全部服务端返回引用用于随后唯一一次消息 POST。
28. Given 一条消息包含超过 4 个图片链接，When Web 投影并显示该消息，Then 只发起前 4 个受控预览，其余链接保留 raw Markdown；任意时刻媒体读取并发不超过 4、缓存不超过 64 MiB。
29. Given 附件上传尚未完成，When 用户确认注销，Then 上传立即收到取消、所有图片草稿 URL 被释放；任何晚到上传结果都不能触发消息 POST。
30. Given 当前用户对一条消息选择 reaction，When Zulip 接受请求，Then UI 使用完整 emoji 三元组更新当前用户状态；外部客户端的 reaction event 也投影到同一计数。
31. Given 当前用户编辑自己的消息，When 保存，Then PATCH 携带 raw Markdown 的 `prev_content_sha256`；若服务端报告冲突，草稿保留并提示刷新后重新确认。
32. Given 当前用户删除自己的消息，When 完成永久删除二次确认，Then只发送一次 DELETE，服务端确认后消息消失；结果未知时消息保留并禁止自动再删。
33. Given 用户收藏或取消收藏消息，When服务器确认，Then只改变当前账号的 `starred` 状态；切换账号或注销后不残留为其他账号状态。
34. Given 本地双击 `start-web-dev.cmd`，When Vite 就绪，Then 打开 `/` 正式登录并直连真实 Realm；fixture 只有显式 fixture/E2E 模式可用且不进入 production bundle。
35. Given 频道或私信组已展开，When 用户点击组标题或用键盘激活，Then 仅该组折叠且当前聊天保持；搜索命中隐藏组时结果临时可见。
36. Given 当前用户在频道详情确认退出，When Zulip 返回 `removed` 或 `not_removed`，Then 该频道的话题、消息、未读和当前选择通过同一 subscription removal reducer 清理；网络结果未知时不自动再次 DELETE。
37. Given 窗口激活且当前会话在消息底部，When 收到该会话中他人的实时新消息，Then follow-scroll 的后续确认不得阻塞一次仅针对捕获会话的标读；服务器成功发布 flags 后才清除未读。切到其他会话、失焦、打开遮罩或标读失败时不得误清。
38. Given Composer 已有可发送正文，When 按普通 Enter，Then 发送一次；When 按 Ctrl+Enter，Then 在原生多行输入框插入换行且不发送；When 中文 IME 正在组合，Then Enter 不触发发送。
39. Given Windows Composer 已聚焦且没有选区，When 光标位于 CJK 文本开头、字符边界或末尾并等待超过系统 caret timeout，Then 始终只有一个不遮字的插入光标，位置贴合真实文本边界且继续按系统周期闪烁。
40. Given Web/Stage 24 历史界面中一个频道含零个、一个或多个话题，When 首次点击该频道，Then 仅该频道在本次运行中展开，并打开记住话题或最新话题；MAUI Stage 25 不提供此入口。
41. Given 频道行被选中、悬停或菜单打开，When 使用行内 `+`，Then 新话题对话框锁定该频道且取消不改变会话或发起 Realm 写入；When 使用更多菜单，Then 菜单仅针对触发行显示设置、置顶/静音切换和退出，`Escape`/外点关闭并恢复触发按钮焦点。
42. Given 从频道行使用 `+`，When 弹窗打开，Then 只显示固定频道名和自动聚焦的话题输入；确认后只切换到本地 `ChannelTopic` 草稿，取消保持原会话，两者都不发送消息或写入 Realm。
43. Given 从频道 A 的更多菜单打开频道设置而当前聊天仍是频道 B，When 浏览、编辑或确认动作，Then 所有读取、权限和写目标始终是频道 A 或设置页内显式选择的频道；旧加载不能覆盖新选择，权限快照失败时全部写入口禁用。
44. Given 宽窗口打开频道设置，When 收窄到 720 DIP 或以下，Then 双栏变为频道列表→详情并可返回；三种列表模式、归档筛选、排序、搜索和四个详情分页仍可操作，关闭后焦点返回原更多按钮。
45. Given 当前用户只拥有添加或移除订阅者中的一种权限，When 打开订阅者页，Then 只启用对应动作；移除需确认，任何请求始终针对设置页所选频道。
46. Given 权限页包含命名组和匿名自定义组，When 修改命名组，Then 请求携带精确 old/new；When 选择匿名组，Then 仅显示其只读状态且不发写请求。
47. Given 用户创建频道，When 选择公开或 Web 公开，Then 历史共享保持开启；When 选择私有，Then 可明确决定后续订阅者是否可见历史。取消不发请求，成功后重新加载并选中新频道。
48. Given 当前消息列表没有新到消息，When 用户向上滚动到真实底部距离严格超过两个当前视口高度，Then 显示“跳转到最新消息”浮动按钮；When 点击且原生列表确认到达最新消息，Then 按钮隐藏。恰好两个视口高度时不显示。
49. Given 任一聊天已打开，When 检查聊天头部，Then 动作区只有搜索和右侧设置；设置只在点击后显示，切换会话会关闭且旧加载不能覆盖新会话。
50. Given MAUI 当前为合格私有群聊，When 打开会话设置，Then 显示权威成员头像、群名、公告、本机备注、查找消息、免打扰、置顶、退出与清本机聊天缓存；详情/权限不可确认时管理与退出失败关闭，成员列表单独失败时不伪造成员。
51. Given 用户确认清聊天记录，When 当前会话是 `ChannelTopic(channelId, "")`，Then 只删除当前账号下该群聊的本机消息、空话题摘要和未读缓存，保留其他群聊、私信、订阅和凭据，且不发服务器删除请求；旧历史响应不能回填缓存。
52. Given 当前为一对一私聊，When 打开会话设置并切换免打扰或置顶，Then 只保存账号隔离的本机偏好；置顶调整本机私信列表顺序，不发用户静音或消息删除请求。
53. Given MAUI 已进入主界面，When 查看窗口并打开设置，Then 常驻内容只有会话列表和聊天两列，不显示头像/消息/联系人/已保存/设置左栏；设置从右上标题栏打开，再次点击同一按钮返回消息区。
54. Given MAUI 已登录，When 查看并点击左上当前用户头像，Then 显示受控加载的本人头像或姓名首字母回退，并在主内容左上打开账号菜单；菜单保留账户设置与注销，右侧设置齿轮仍独立打开应用设置。
55. Given MAUI 已打开设置页，When 在宽屏左侧目录或窄屏顶部分类栏点击“返回聊天”，Then 返回当前消息区并保留原会话；无需再次猜测点击标题栏齿轮，也不发 Realm 请求。
56. Given MAUI 主窗口已显示，When 查看产品标题栏，Then 左侧没有独立 `R` 图标且当前用户头像位于 RelayCove 标题之前；右侧账号头像已移除，只保留设置、主题、置顶和系统窗口按钮。
57. Given register 同时包含公开、Web-public、旧多话题私有频道、group-DM、一对一/self-DM 和合格私有空话题群，When MAUI 投影列表与搜索，Then 只出现后一对一/self-DM 与合格群聊，且按置顶、最新时间、规范键排序。
58. Given 用户打开 `+`，When 选择私聊，Then 只能选一人；When 选择群聊，Then 必须填写群名并选择至少两名其他活跃成员。创建权限快照缺失或拒绝时群聊入口禁用并显示原因。
59. Given 群聊创建请求结果不确定，When 客户端恢复，Then 不重复 POST，而是重新 register 并把权威订阅投影回统一列表，提示用户先核对是否已创建。
60. Given 三项管理权限明确为同一直接成员，When 群主打开设置，Then 可见改名、公告、邀请、移人、转让和解散；When 权限结构复杂或详情加载失败，Then 只保留已确认安全的个人设置且不推断群主。
61. Given 群主转让，When 三项权限已原子更新并重新读取确认，Then 才尝试旧群主退出；第二阶段失败时显示“已转让但尚未退出”且不重复第一阶段。
62. Given 群主解散，When 其他成员全部移除并重新读取确认只剩群主，Then 才让群主退出；并发新增、结果不确定或仍有成员时停止，服务器私有历史不删除。
